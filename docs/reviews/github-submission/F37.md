## Summary

The dark visual system is reasonably consistent, but titlebar/action text is small, advanced controls dominate the canvas at the tested viewport, and the dock/minimap compete for space. Model cards retain large empty preview areas when remote thumbnails fail. Important state is spread across the toolbar, sidebar, settings, hub, and modal dialogs.

## Environment and evidence

- Review finding: **F37** (2026-10-05 product/technical review).
- Baseline: Windows, `dev` at [c1c5dbe](https://github.com/BerryUIKI/AI-Studio/commit/c1c5dbeaace01fc5e3fa68d8e3ebf410583b775b). The remote `dev` matched this commit when filing.
- Evidence: **Browser; qualitative assessment**.
- Priority recommendation: **P2 - material improvement or integration validation**. This is review triage, not a production-incident severity declaration.
- No real credentials, paid inference, engine installation, or unrelated process termination were used for review probes. Mocked observations establish the stated code behavior, not live-provider/GPU acceptance.

## Reproduction or validation

Browser review at approximately 1060 x 612 found small toolbar/action text, advanced controls competing with the canvas, dock/minimap competition, and large blank model previews after thumbnail errors. These are qualitative observations; the native minimum 1024 x 700 layout was not exercised and no failure at that minimum is claimed.

## User impact

Users spend attention finding status/configuration rather than reviewing creative results.

## Proposed approach

Establish one primary action, progressive disclosure for advanced controls, reliable thumbnail fallbacks, a clear task/status area, and test native minimum size, 125%/150% display scaling, and common laptop sizes. The screenshot alone does not establish failure at the native minimum height.

## Acceptance criteria

- [ ] Establish a clear primary action and progressive disclosure for advanced controls.
- [ ] Provide meaningful local thumbnail fallbacks.
- [ ] Consolidate task/readiness feedback in a discoverable area.
- [ ] Validate native minimum size, common laptop sizes, and 125%/150% display scaling.
- [ ] Record task-based usability evidence before declaring layout acceptance.
