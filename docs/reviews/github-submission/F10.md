## Summary

For `engine_id=fal_ai`, `model=sdxl-turbo`, the hash/provider resolver selected Fal, but [creative_runner.py:627](https://github.com/BerryUIKI/AI-Studio/blob/c1c5dbeaace01fc5e3fa68d8e3ebf410583b775b/backend/app/runners/creative_runner.py#L627) dispatched to SiliconFlow when both dummy keys were available. The resolver and executor contain separate heuristic decision trees.

## User impact

The selected provider, actual service, credential use, cache identity, and provenance can diverge. This also affects users' expectations about cost and asset destination.

## Proposed approach

Resolve a single capability-checked execution plan before submission and use it for validation, dispatch, hashing, UI disclosure, and provenance. Reject unsupported combinations rather than silently switching providers.

- [ ] Resolve one capability-checked execution plan before submission.

- [ ] Explicit provider selection cannot silently switch to another service.
