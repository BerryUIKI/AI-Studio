## Summary

The empty canvas lacks a clear guided first task. Generate remains available with an uninstalled default engine; model selection exposes a filename field. Cloud is represented as a generic execution choice even though providers support different actions and parameters.

## Reproduction or validation

Open Berry with no engines/models/keys configured. The empty canvas has no clear first task, Generate can target an uninstalled default engine, model entry exposes a filename, and Cloud is generic despite differing provider capabilities. Browser observation and code review were used; no paid generation was submitted.

## User impact

A new user reaches a technical failure before understanding the setup choice.

## Proposed approach

Offer an obvious cloud/local setup path, a validated model/provider picker, readiness checks with a direct repair action, capability-specific controls, and a short default prompt that can produce a first result without node wiring.

## Acceptance criteria

- [ ] Provide clear cloud/local setup and a first-image action.
- [ ] Select only ready compatible providers/models or offer a direct repair path.
- [ ] Basic controls match the chosen action/provider capabilities.
- [ ] A clean user reaches a first cloud image without local GPU dependencies or node wiring.
