## Summary

Importing the 640 x 360 fixture displayed 512 x 512 and a 1024 x 1024 2x target. [useCreativeStore.ts:287](https://github.com/BerryUIKI/AI-Studio/blob/c1c5dbeaace01fc5e3fa68d8e3ebf410583b775b/frontend/src/stores/useCreativeStore.ts#L287) supplies 512 defaults because stored dimensions are absent. [creative_runner.py:185](https://github.com/BerryUIKI/AI-Studio/blob/c1c5dbeaace01fc5e3fa68d8e3ebf410583b775b/backend/app/runners/creative_runner.py#L185) overwrites dimensions from aspect ratio for all actions. The Comfy upscale graph uses the model's native scale rather than applying the chosen factor, and the result metadata uses requested dimensions.

## Reproduction or validation

1. Open Berry with an empty disposable library.
2. Import the attached 640 x 360 PNG.
3. Select the image and open Upscale.
4. Choose 2x.
Observed: Current=512 x 512 and Target=1024 x 1024.
Separately, aspect-ratio normalization overwrites action dimensions and the Comfy upscale graph uses the upscaler's native factor without applying the requested scale. No real upscale inference was run.

## User impact

The preview, requested size, actual result, and export metadata can disagree.

## Proposed approach

Decode actual dimensions on adoption, preserve source ratio, implement requested scaling explicitly, and derive result metadata from the output.

## Acceptance criteria

- [ ] Decode and store actual adopted-image dimensions.
- [ ] The upscale preview preserves source ratio and reflects the requested factor.
- [ ] Apply the requested factor explicitly when an upscaler has a different native scale.
- [ ] Derive result metadata from decoded output rather than requested dimensions.
- [ ] Test non-square imports and both supported upscale factors end to end.
