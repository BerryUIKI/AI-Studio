## Summary

Image export actions commonly force a `.png` filename rather than converting or retaining the actual format. Explicit `.webp`/`.gif` URLs are handled as images, but Berry returns extensionless managed-asset URLs; a video-tagged animated WebP at such a URL follows the HTML video branch. Cloud source encoding also assumes an image MIME type rather than the decoded format.

## Reproduction or validation

Inspect ImageCardNode with mediaType=video and a managed URL such as /api/v1/assets/<id>/content. Its extension test cannot identify animated WebP at that URL and selects the video element. Explicit .webp/.gif URLs are already handled separately. FloatingCardToolbar forces png/mp4 names, and image-card export often guesses from an extensionless URL. This is code evidence, not a live generated-video reproduction.

## User impact

Exported files have misleading extensions, some generated media cannot preview, and provider input validation may fail.

## Proposed approach

Track verified MIME/codec/extension, render animated images versus playable video appropriately, and either export original content correctly or perform an explicit conversion.

## Acceptance criteria

- [ ] Track verified MIME, codec, and extension in the asset/card contract.
- [ ] Render animated images and playable video using media metadata, including extensionless URLs.
- [ ] Export original content with a correct extension or perform an explicit conversion.
- [ ] Provider upload MIME matches decoded source content.
- [ ] Tests cover JPEG, animated WebP, GIF, and MP4 managed assets.
