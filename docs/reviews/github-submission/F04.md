## Summary

A text item disappeared after browser reload. [useCanvasStore.ts:48](https://github.com/BerryUIKI/AI-Studio/blob/c1c5dbeaace01fc5e3fa68d8e3ebf410583b775b/frontend/src/stores/useCanvasStore.ts#L48) initializes an in-memory canvas, and the frontend does not connect this state to the backend project CRUD API. Database project tests exercise storage primitives rather than saving and reopening the actual application canvas.

## Reproduction or validation

1. Open Berry with a disposable data directory.
2. Add a Text Input canvas item and change its position/content.
3. Reload the browser and return to the canvas.
4. Observe that the item and layout are gone.
The frontend canvas store initializes in memory and does not call the backend project CRUD routes.

## User impact

Users can lose layout, selections, relationships, and their working context on restart. This directly fails R15.

## Proposed approach

Create/open/save/autosave a versioned project containing canvas layout, asset references, lineage, and generation history. Test restart recovery and missing-file handling through the UI.
