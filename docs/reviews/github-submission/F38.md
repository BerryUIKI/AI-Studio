## Summary

Several modal implementations lack consistent dialog semantics, focus trapping/restoration, and Escape handling. Icon-only controls have incomplete accessible names, clickable model cards are not consistently keyboard-operable, and labels are not always associated with inputs. Hidden mounted canvas views retain global keyboard handlers that do not cover all editable/focusable contexts.

## Reproduction or validation

Review dialog roles, focus behavior, input labeling, icon-control names, and keyboard activation of clickable cards. Several implementations lack a common accessible contract. ViewContainer keeps hidden canvas views mounted, so global shortcut handlers remain active and do not cover all editable/focusable contexts. Validate through keyboard-only workflows and the accessibility tree.

## User impact

Keyboard/screen-reader users struggle to operate the app, and shortcuts can affect the canvas from another view.

## Proposed approach

Standardize accessible modal/control primitives, scope shortcuts to the active view and focus context, and test keyboard-only creation, editing, cancel, export, and navigation.

## Acceptance criteria

- [ ] Dialogs expose appropriate semantics, focus trapping/restoration, and Escape handling.
- [ ] Inputs and icon-only controls have meaningful accessible names.
- [ ] Cards/actions are keyboard-operable.
- [ ] Canvas shortcuts only act in the active canvas and respect editable focus.
- [ ] Keyboard-only create/edit/cancel/export/navigation passes.
