## Summary

A mocked successful `LlamaServerSupervisor.stop()` returned `None`, despite its dictionary return annotation. [main.py:152](https://github.com/BerryUIKI/AI-Studio/blob/c1c5dbeaace01fc5e3fa68d8e3ebf410583b775b/backend/app/main.py#L152) automatically starts the first available local model at backend startup. The runtime uses a fixed port and starts without awaiting service readiness; local-provider configuration can appear ready before installation/health is established.

## Reproduction or validation

Mock LlamaServerSupervisor.get_pid, subprocess.run, and PID cleanup, then call stop: successful termination returns None despite its dictionary annotation. No real process was terminated. Source review also found automatic startup of the first local model, fixed-port use, and no awaited readiness before reporting start success.

## User impact

Stop callers cannot rely on a result, startup can unexpectedly consume resources, and the Agent can appear available while its service is unavailable.

## Proposed approach

Return explicit lifecycle results, honor a saved opt-in/start preference, select a known model, check port ownership, and report health separately from installation and PID state.

## Acceptance criteria

- [ ] All start/stop paths return explicit structured results.
- [ ] Local startup follows a saved opt-in preference and selected model.
- [ ] Check port ownership and service readiness independently of PID existence.
- [ ] Provider configuration is not presented as readiness when runtime/model is missing.
- [ ] Tests cover absent/starting/healthy/failed services and successful stop.
