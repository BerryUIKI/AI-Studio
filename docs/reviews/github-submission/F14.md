## User impact

An engine can be updated during ordinary canvas generation, and a reported rollback can leave a mismatched runtime.

## Proposed approach

Use one task/lifecycle registry and an exclusive update lease; stage a complete new runtime, validate it, and switch atomically. Roll back both code and dependencies.

## Acceptance criteria

- [ ] Workflow and creative tasks share one authoritative lifecycle registry.
- [ ] An exclusive update lease rejects work/update races and rechecks live state.
- [ ] Update stages a complete compatible runtime before switching.
- [ ] Rollback restores code and dependencies and leaves the engine in a recoverable state.
