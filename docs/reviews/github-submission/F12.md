## Summary

An existing empty ComfyUI directory, with mocked venv creation, was reported `completed` despite having no `main.py`. [installer.py:161](https://github.com/BerryUIKI/AI-Studio/blob/c1c5dbeaace01fc5e3fa68d8e3ebf410583b775b/backend/app/runtime/installer.py#L161) skips cloning for any existing destination, and missing prerequisites can bypass dependency setup. Separately, [installer.py:56](https://github.com/BerryUIKI/AI-Studio/blob/c1c5dbeaace01fc5e3fa68d8e3ebf410583b775b/backend/app/runtime/installer.py#L56) changes an in-progress manifest to `interrupted` whenever it is read, including ordinary live status polling.

## Reproduction or validation

Two isolated probes expose the installation-state contract. (1) Create an empty ComfyUI destination and mock venv creation as successful; install_engine reports completed with no main.py. (2) Write a DOWNLOADING manifest and read it through read_manifest; it becomes INTERRUPTED even though a live status read should not invalidate an active worker. No repository clone or package installation was performed.

## User impact

Installed state is unreliable, retry can preserve broken directories, and the UI can misreport an installation while it is still running.

## Proposed approach

Distinguish an active worker from a previous interrupted attempt, lock operations per engine, install into staging, and mark completion only after entrypoint, dependency, and smoke-health validation.

## Acceptance criteria

- [ ] Distinguish active installation workers from interrupted previous runs.
- [ ] Status reads are side-effect-free for active installations.
- [ ] Missing entrypoint, dependency setup, or validation prevents completed state.
- [ ] Per-engine locking and staged promotion preserve existing working installations.
- [ ] Interrupted and empty-directory retries recover without false success.

## Verification scope

Real GPU inference, paid-provider compatibility, and a clean-machine packaged desktop journey remain unverified. Any follow-up implementation should target `dev` under the repository's contribution/branching rules.
